# 模组定位与数据结构

HanShu-Item 只管理编号物品的原生 NBT 存储、取出与同步。

一个编号定义包含物品类型 icon、原生组件补丁 nbt（SNBT）和统一同步排除路径 sync-exclude。
不引入独立的玩法数据区，不解释枪械模组的弹药字段，也不接管其他模组的物品行为。

物品 CUSTOM_DATA 中的 hanshu_item 子节点仅记录 id、def、rev，即编号归属和模板签名。
同步规则仅记录在编号 JSON 的 sync-exclude 中，同编号物品共享，不含单件规则或 data 子节点。

组件编解码使用 Minecraft 的 DataComponentPatch CODEC 和 NbtOps，并带当前注册表上下文。
因此可保留文本组件、附魔、属性、原生 NBT 类型、long 精度、数组及可持久化的第三方组件。

同步触发依据是模板或规则的签名变化，正常射击或耐久消耗不会因为改变 NBT 而反复重建。
同步排除路径读取物品现有值，在应用模板后恢复它；原本缺失的排除字段仍然缺失。

指令、文件位置和弹药保护示例见[物品管理指令](物品管理指令.md)。
