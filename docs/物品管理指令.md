# 原生 NBT 物品管理

模组只负责把物品的原生数据组件保存为编号模板、取出模板物品，以及更新同编号物品。
不再提供自定义 data 数据区、技能、冷却、品质、随机词条、动作绑定或展示模板。

## 指令

管理指令需要 OP 权限。

| 指令 | 用途 |
| --- | --- |
| `/hanshu save <编号>` | 将主手物品原生组件保存到编号；已有编号会被覆盖，并绑定主手物品 |
| `/hanshu get <编号> [数量]` | 取出编号物品；默认 1，范围 1–64 |
| `/hanshu list` | 列出编号 |
| `/hanshu info` | 查看主手编号及同步排除路径 |
| `/hanshu unbind` | 移除主手物品的同步编号，使其不再参与自动同步 |
| `/hanshu bind <编号>` | 将主手物品绑定到已有编号，并立即按模板同步 |
| `/hanshu sync [编号]` | 同步内存中落后的编号物品 |
| `/hanshu rules set <路径> on\|off [编码ID]` | 设置指定编号的字段同步规则；省略 ID 时使用主手编号 |
| `/hanshu rules list [编码ID]` | 查看指定编号的同步排除规则；省略 ID 时使用主手编号 |
| `/hanshu rules reset [编码ID]` | 清除指定编号的全部排除规则；省略 ID 时使用主手编号 |

保存不消耗物品；已有编号会被当前主手物品覆盖。编号支持 `1001`、`weapons/1001`、
`custom:weapons/1001` 等形式。编号参数支持 Tab 补全。
取出数量按实际最大堆叠数拆分，背包放不下的部分掉落在玩家身旁。

`/hanshu unbind` 只移除物品 `CUSTOM_DATA` 中的 `hanshu_item` 管理节点，
包括编号和签名；物品其它原生 NBT、组件和第三方数据都会保留。编号 JSON 不会被删除，
之后仍可使用 `/hanshu get <编号>` 取出新物品，或再次保存/绑定该物品。

绑定已有编号时使用：

```text
/hanshu bind hanshu_item:example_scroll
```

绑定要求主手物品的基础类型与编号 JSON 的 `icon` 一致；类型不一致时不会改动物品，
请改用 `/hanshu get <编号>`，或用 `/hanshu save <编号>` 覆盖模板。

`/hanshu get <编号>` 使用对应 JSON 的 `icon` 作为基础物品，再应用 `nbt` 中的原生组件。
如果取出后显示为普通纸，先执行 `/hanshu info` 或 `/hanshu list` 检查该编号的 `icon` 是否为
`minecraft:paper`；原生 NBT 不会自动把纸变成自定义物品。自定义外观需要填写实际模组物品 ID，
或在模板 NBT 中保存对应的 `minecraft:item_model` / `minecraft:custom_model_data` 组件。

## 保留枪械弹药等原生状态

假设枪械模组把剩余弹药放在原生 CUSTOM_DATA 的 `GunCurrentAmmoCount` 中：

```text
/hanshu save 1001
/hanshu rules set nbt.GunCurrentAmmoCount off
/hanshu rules list
```

模板是 30 发、主手枪剩余 7 发时，关闭该字段后，同步其他字段仍保留 7 发。
字段名须以实际枪械模组的 NBT 为准，以上只是示例。

```text
/hanshu rules set nbt.GunCurrentAmmoCount on
/hanshu rules set nbt.GunState off
/hanshu rules set components."minecraft:damage" off
/hanshu rules reset
```

可以在指令末尾直接指定编码 ID，不需要手持该编号物品：

```text
/hanshu rules set nbt.GunCurrentAmmoCount off weapons/ak_47
/hanshu rules list weapons/ak_47
/hanshu rules reset weapons/ak_47
```

编码 ID 是字符串，沿用编号库格式，如 `001`、`ak_47`、`weapons/ak_47`、
`custom:weapons/ak_47`；不会把数字形式转成整数，`001` 与 `1` 是两个不同编号。
显式 ID 优先于主手物品，支持 Tab 补全，服务端控制台也可指定 ID 使用这些指令。

`nbt` 是 `components."minecraft:custom_data"` 的别名。
同步执行和规则管理分开：`sync` 只执行同步，`rules` 管理编号规则；路径中的 `nbt.` 表示物品原生 NBT 的字段位置。
父节点关闭会保留整棵子树；组件也可整项关闭。路径可使用带引号的键名和列表下标。
不参与同步的字段在物品上原本不存在时，同步后仍保持不存在。
模板没有涉及的第三方键会保留；模板里的参与字段用模板值覆盖。

指令使用输入的编码 ID，省略时读取主手物品的编号，将规则直接保存到该编号 JSON 的 `sync-exclude` 中，
并同步已加载的同编号物品。规则对该编号的所有物品生效，重启后仍保留；不写入物品 NBT。
`on` 清除对应路径及其子树的排除规则，`reset` 清除该编号全部排除规则，恢复全部字段参与同步。
省略 ID 且主手物品没有编码 ID 时，向执行者报错，不修改任何规则。
显式 ID 找不到定义时也报错，不会退回主手编号；非玩家执行者必须指定编码 ID。
如果编号本身叫 `set`、`list` 或 `reset`，手动同步时使用完整编号，例如 `/hanshu sync hanshu_item:list`。
启用编辑页面后，编号模板和主手 NBT 编辑页面的同步勾选也写入相同 JSON。
编辑单件物品的值不会自动修改整个编号的同步规则，需要保留某个字段时须明确取消同步勾选。

## 配置与文件

编辑页面默认关闭。在 `config/hanshu_item-common.toml` 中设置
`enableEditor = true` 可启用 K 键编号库、L 键物品选择器。
编辑器直接显示原生组件树，支持逐字段勾选同步。

编号定义保存在 `config/hanshu_item/items/<命名空间>/<编号>.json`：

```json
{
  "icon": "minecraft:diamond_sword",
  "nbt": "{\"minecraft:custom_data\":{AmmoCount:30},\"minecraft:damage\":17}",
  "sync-exclude": ["components.\"minecraft:custom_data\".AmmoCount"]
}
```

NBT 以 SNBT 字符串存储，保留数值类型、long 精度、数组、文本样式、附魔及第三方组件。
物品的 `hanshu_item` 管理节点仅保留 `id`、`def`、`rev`，不含排除路径或 `data`。
旧物品上的 `hanshu_item.exclude` 不再参与同步，也不会自动合并到编号 JSON；
物品下次同步时清除旧标记。若曾使用单件排除规则，请用上述指令重新设置编号规则。

此前通过 save 捕获的 `meta.components` 原生模板仍能加载；再次保存会写为新格式。
旧版 data、技能、冷却、词条和展示配置不再执行。
