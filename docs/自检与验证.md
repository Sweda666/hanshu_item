# 自检与验证

项目构建目标是 Minecraft 26.1.2、Forge 64.1.3，Java 工具链要求 JDK 25。
在项目根目录编译并导出运行时类路径：

```text
.\gradlew.bat compileJava printCheckClasspath
```

类路径写入 `build/check-classpath.txt`。PowerShell 执行示例：

```powershell
$checkClasspath = (Get-Content -LiteralPath build/check-classpath.txt -Raw).Trim()
java -cp $checkClasspath sweda.hanshu_item.overture.runtime.NativeNbtSyncCheck
```

其余检查替换最后的完整类名即可。应使用 Java 25 运行，并先成功编译，避免执行旧的 class。

| 自检类 | 检查内容 |
| --- | --- |
| sweda.hanshu_item.overture.runtime.SavedItemComponentsCheck | 原生组件保真往返、精简后的指令树与可选编号解析、管理节点清理 |
| sweda.hanshu_item.overture.runtime.NativeNbtSyncCheck | 30 发模板与 7 发枪械的排除同步、父节点、缺失字段、组件移除、带引号键名、列表下标 |
| sweda.hanshu_item.overture.runtime.LibraryLoadCheck | 非法模板保留旧快照、规则写入对应 JSON、重载保留、编号隔离、重置及写盘失败回滚 |
| sweda.hanshu_item.overture.model.SyncFlagsCheck | 父子排除规则及序列化 |
| sweda.hanshu_item.overture.model.FileChangeDetectorCheck | 写入稳定性、内容去重和原子写盘 |
| sweda.hanshu_item.client.EditorLayoutCheck | 编号列表布局 |
| sweda.hanshu_item.client.RawNbtLayoutCheck | 原生 NBT 编辑页面布局 |

服务端启动后，ItemSyncService.selfTest 在物品组件已绑定的真实游戏环境中
检查每个编号能否构建、同步，以及签名和组件比较是否收敛；额外使用临时物品验证弹药保留、
旧 data / exclude 子树清理、参与字段漂移恢复，以及删除 JSON 排除后恢复同步。
`SavedItemComponentsCheck.main` 不执行需要真实注册表的 `checkNativeRefresh`；该部分由服务端自检调用。
临时物品不会发放或写入编号库，自检结果记录在日志中。

## 游戏内回归检查

1. `/hanshu save test` 保存主手物品，确认对应 JSON 的 `icon` 和 `nbt`；修改物品后再次保存，确认允许覆盖。
2. `/hanshu get test 2` 取出两件，确认原生名称、Lore、附魔和第三方组件与模板一致。
3. 铁砧修改其中一件的模板名称且不 save，确认玩家定时检查会恢复名称。
4. 使用目标枪械模组确认实际弹药路径，在射击前关闭该路径同步，确认弹药变化保留、其它参与字段仍更新。
5. `rules` 分别指定编号和省略编号；无主手编号时应报错，规则只应保存到编号 JSON。
6. `unbind` 后确认物品失去编号、保留原生数据且不再恢复模板值；`bind test` 后恢复同步。
7. 修改服务端 JSON，等待稳定重载；写入非法 JSON/SNBT 后确认保留旧定义并记录错误。
8. 在背包、容器打开、区块加载和重进游戏场景检查更新，按[物品同步](物品同步.md)限定的范围判断结果。
9. 默认 K/L 不打开页面；开启 `enableEditor` 后验证本地页面和同步勾选。

文档更新不等于这些检查已经执行。发布前应记录实际使用的 JDK、Minecraft/Forge 版本及目标模组测试结果。
