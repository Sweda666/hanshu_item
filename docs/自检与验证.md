# 自检与验证

先编译并导出运行时类路径：

```text
gradlew.bat compileJava printCheckClasspath
```

类路径写入 build/check-classpath.txt。以下自检可用 Java 25 的 java -cp 执行：

| 自检类 | 检查内容 |
| --- | --- |
| sweda.hanshu_item.overture.runtime.SavedItemComponentsCheck | 原生组件保真往返、编号解析、管理节点不含同步规则 |
| sweda.hanshu_item.overture.runtime.NativeNbtSyncCheck | 30 发模板与 7 发枪械的排除同步、父节点、缺失字段、组件移除、带引号键名、列表下标 |
| sweda.hanshu_item.overture.runtime.LibraryLoadCheck | 非法模板保留旧快照、规则写入对应 JSON、重载保留、编号隔离、重置及写盘失败回滚 |
| sweda.hanshu_item.overture.model.SyncFlagsCheck | 父子排除规则及序列化 |
| sweda.hanshu_item.overture.model.FileChangeDetectorCheck | 写入稳定性、内容去重和原子写盘 |
| sweda.hanshu_item.client.EditorLayoutCheck | 编号列表布局 |
| sweda.hanshu_item.client.RawNbtLayoutCheck | 原生 NBT 编辑页面布局 |

服务端启动后，ItemSyncService.selfTest 在物品组件已绑定的真实游戏环境中
检查每个编号能否构建、同步，以及签名是否收敛；额外使用临时物品验证弹药保留、
旧 data / exclude 子树清理，以及删除 JSON 排除后恢复同步。临时物品不会发放或写入编号库。

建议在装有目标枪械模组的游戏里实测：
保存枪械、查询实际弹药字段、关闭该字段同步、射击后修改模板其他字段，
确认剩余弹药保留且其他字段更新。
