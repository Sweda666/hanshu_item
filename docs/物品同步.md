# 编号物品的原生 NBT 同步

模板变化后，同编号物品应用新的原生组件值。排除字段保留物品自己的值，
例如枪械剩余弹药、膛内子弹或换弹状态；第三方模组继续负责这些字段的实际使用逻辑。

管理规则作用于真实的组件 NBT 路径，没有独立的玩法 data 数据区。
nbt 是 components."minecraft:custom_data" 的别名。
同步规则仅来自物品编号对应 JSON 的 sync-exclude，同编号物品使用相同规则。
指令使用末尾指定的字符串编码 ID；省略时读取主手编号，没有主手编号则反馈错误。
规则保存到对应 JSON，编辑页的同步勾选也保存到编号 JSON。
物品 NBT 不再保存规则；旧 exclude 标记在下次同步时清除，不会合并到 JSON。
执行 `/hanshu unbind` 可主动移除手持物品的编号管理节点；移除后该物品不会再被自动同步，
但其它原生 NBT 和编号 JSON 都保留。

## 何时需要更新

除了检查模板和规则签名，也会把模板合并到物品当前组件后比较结果。
因此模板不变时，铁砧改名、第三方模组修改参与字段等漂移也会恢复。
弹药、耐久、换弹状态等动态字段若在模板中且未被排除，也会恢复为模板值。
排除字段的变化不会单独触发重建。

## 触发与扫描范围

| 触发 | 检查范围 |
| --- | --- |
| 玩家每 10 tick、登录和退出 | 玩家背包、装备、副手及当前菜单光标物品 |
| 打开容器 | 菜单槽位 |
| 区块加载 | 该区块实现 `Container` 的方块实体 |
| save 或编辑器调用保存定义 | 在服务端安排全服扫描 |
| rules set/reset | 立即扫描指定编号 |
| 定义文件稳定变化 | 受影响编号；涉及超过 64 个编号时改为全服扫描 |
| 内存定义变化或手动 sync | 全服扫描，或按指定编号筛选 |

全服扫描包含各维度已加载掉落物、在线玩家及当前菜单、玩家视距内已加载区块的容器。
不会加载远处区块，也不扫描离线玩家存档；远处已强制加载的容器不能保证被本轮扫描覆盖。
离线玩家下次登录、区块下次加载或容器打开时会补检查。
容器和掉落物没有每 10 tick 的漂移检查；该频率仅用于玩家物品。

`get` 创建新物品时使用完整模板，排除字段也会获得模板初始值。
`bind` 绑定已有物品时按规则合并；解绑后再绑定也会重新参与同步。

## 文件监听

定义文件和内存变化各每 100 tick 检查一次。按正常 20 TPS，玩家检查间隔约 0.5 秒，
文件轮询间隔约 5 秒；外部写入需连续两轮指纹稳定后重载，通常在保存后约 5–10 秒生效。
非法 JSON、SNBT 或路径不替换旧快照；单文件写入采用临时文件加原子改名，
文件系统不支持原子移动时退回普通替换。多文件保存不保证整体原子性。
以 config/hanshu_item/items 下的分文件定义为准，也兼容首次加载旧聚合 items.json。
