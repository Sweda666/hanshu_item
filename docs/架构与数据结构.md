# 原生 NBT 物品库架构

| 组件 | 职责 |
| --- | --- |
| ItemDefinition / DefinitionJson | 编号、类型、原生 SNBT、排除路径的不可变定义及 JSON 编解码 |
| DefinitionStore / ModItemLibrary | 校验、候选快照提交、编号 JSON 同步规则持久化及写盘失败回滚 |
| SavedItemComponents | 原生组件 CODEC 与 SNBT 往返，移除来源编号管理信息 |
| NativeNbtSync | 合并模板与当前组件，按原生 NBT 路径恢复排除字段 |
| ModItemBuilder | 构建编号物品、刷新组件、记录模板签名并检查参与字段的漂移 |
| ItemDataAccessor | 原生 CUSTOM_DATA 读写和最少的编号管理信息 |
| ItemSyncService / ItemSyncHooks | 定义变化扫描、玩家每 10 tick 漂移检查、登录/容器/区块事件同步 |
| DefinitionFileWatcher / LibraryWatcher | 检测文件和内存模板变化 |
| OvertureCommands | 注册 save/get/list/info/bind/unbind/sync/rules 指令 |
| RawNbtScreen / LibraryNbtScreen / ItemListScreen / ItemPickerScreen | 可选的客户端原生组件编辑、编号库及物品选择页面 |

## 数据流

`save <编号>` 捕获主手物品类型和组件补丁，去除来源管理节点，保留目标编号已有的排除规则，
校验后保存 JSON 并给主手物品写入编号签名。`get` 按 `icon` 创建新物品，再应用完整模板补丁。

刷新已有物品时先合并模板和当前补丁，再恢复排除路径的现有值，解码成功后应用组件并更新签名。
模板或规则签名变化、旧管理字段存在、参与同步的字段偏离模板，都会被判定为需要更新。

## 持久化与边界

定义使用 `config/hanshu_item/items/<命名空间>/<编号路径>.json` 分文件保存。
JSON 包含 `icon`、`nbt` 和可选的 `sync-exclude`；物品只保存 `hanshu_item.id/def/rev`。
单文件写入使用临时文件和原子移动（不支持时退回普通替换），多文件保存不是整体事务。
非法候选定义不替换内存快照；保存或规则写盘失败会恢复相应旧定义。

自动扫描不会强制加载区块。全服扫描检查各维度已加载掉落物、在线玩家及当前菜单、
玩家视距内已加载区块的 `Container` 方块实体；不能据此保证覆盖远处的强制加载区块或模组私有存储。
客户端编辑器直接访问本地定义库，目前没有向远程服务器提交编辑的网络协议。
刷新已绑定物品只更新组件，不替换基础物品类型；更改定义 `icon` 后使用 `get` 创建新类型物品。
